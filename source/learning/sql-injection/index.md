## 学习顺序

### 第一阶段：认识输入面

先理解“用户输入”不只来自表单和 URL。HTTP 请求头、Cookie、日志字段和 API JSON 都可能进入数据库查询。

- [SQL 注入中的请求头与 Cookie 输入面](/2025/05/21/SQL注入中的请求头与Cookie输入面/)

### 第二阶段：识别数据库差异

不同数据库的系统表、函数和语法并不相同。确认数据库类型应服务于最小化验证和修复，而不是无目的地获取数据。

- [SQLite 注入与 Next.js 页面入口分析](/2026/05/07/SQLite注入与Nextjs入口分析/)

### 第三阶段：理解权限放大

SQL 注入的最终影响取决于数据库账户权限、文件系统权限、部署目录和应用架构。能够执行查询并不必然意味着能够写入文件或执行代码。

- [SQLi-Labs 文件导出注入：权限条件与防御](/2025/05/15/SQLi-Labs文件导出注入/)

## 学习检查表

- 能否判断输入进入了哪一条查询语句？
- 能否说明注入成立需要哪些前置条件？
- 能否用最小请求证明问题，而不获取无关数据？
- 能否定位到字符串拼接或错误的数据访问代码？
- 能否给出参数化查询、最小权限和监控三层修复方案？
